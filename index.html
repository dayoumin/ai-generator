이 앱 사용하는 순서

설정부터 결과 확인까지 가장 짧게 가려면 이 순서를 따르면 됩니다.

1

Compose 열기

Compose가 메인 작업공간입니다. 프롬프트, Scene Planner, 템플릿, 레퍼런스, 실행 설정이 한곳에 모여 있습니다.

2

모드, 렌더러, 운영 방식 선택

직접 렌더는 prompt-first 흐름을 유지하고, 보조 렌더는 먼저 장면 구조를 만듭니다. 렌더러는 실제 픽셀을 어디서 만들지 정하고, 운영 방식은 앱 내부 실행인지 Codex 대화 연동인지 정합니다.

3

장면 구성

프롬프트를 불러오고 스타일을 조정한 뒤, 장면 Planner를 채우고 장면 템플릿과 레퍼런스를 적용합니다.

4

프리플라이트 확인 후 시작

Compose의 preflight 패널에서 누락된 레퍼런스, 지원되지 않는 조합, 모드별 경고를 먼저 확인하고 시작합니다.

5

Outputs는 단계적으로 사용

먼저 갤러리를 검수하고, 더 깊은 비교나 반복 수정이 필요할 때만 비교, 재시도 제안, lineage, Codex handoff를 엽니다.

누가 무엇을 준비하나

공용 스튜디오와 각 프로젝트의 책임을 분리해 두면 시간이 지나도 다시 쓰기 쉽습니다.

AI_Generator에서 준비

프로젝트 선택, 프롬프트 로드, 레퍼런스 자산 선택, 배치 생성, 크롭, manifest, 업로드 같은 공용 스튜디오 기능을 담당합니다.

각 프로젝트에서 준비

프롬프트 파일, reference-assets, 크롭 규칙, inject 로직 같은 이미지 명세와 자산은 각 프로젝트가 제공합니다.

생성 방식

하나의 구조로 여러 생성 엔진과 운영 방식을 함께 쓸 수 있게 설계합니다.

1. 로컬 모델

ComfyUI 기반 로컬 생성. 현재 기본 모드이며 반복 생성과 빠른 수정에 적합합니다.

2. API 모델

외부 이미지 API 사용. 핵심 컷만 고품질로 뽑거나 특정 스타일이 필요할 때 사용합니다.

3. Codex 보조 생성

Codex가 프롬프트, 레퍼런스 자산, 프로젝트 설정, 검수 루프를 운영하고 실제 픽셀 렌더링은 ComfyUI나 API가 담당합니다.

3번째 방법은 어떻게 쓰나?

Codex가 프로젝트 설정과 자산 구조를 만들고, 어떤 provider를 쓸지 결정하고, 생성 결과를 보고 다시 프롬프트를 조정합니다. 즉 렌더러는 엔진, 운영자는 Codex인 구조입니다.

왜 서버가 2개인가?

ComfyUI는 GPU로 이미지를 생성하는 독립 오픈소스 AI 엔진입니다. AI_Generator는 ComfyUI의 API를 호출하는 관리 도구입니다. 자동차에 비유하면 ComfyUI가 엔진, AI_Generator가 운전석입니다.
